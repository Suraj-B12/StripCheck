\section{Limitations, ethics and safety}
\label{sec:limits}

\subsection{Limitations}
A \NLISTED{} verdict is only as good as the lists behind it. CDSCO tests samples, so most batches on the market are never tested, and an unlisted batch can still be substandard; StripCheck states this on every such result and shows how recent its lists are. Every pack in the evaluation and in the demonstrations is synthetic: we rendered the packs from alert rows and took no photos of real medicine strips. Rendered packs flatter OCR, and embossed foil, curved bottles and poor light produce confusions the table may not contain, so the results say nothing yet about accuracy on real strips. Labels are read in English only. The oracle user answers every question perfectly, while real people may misread the pack or skip the question. Each scenario has few packs, so small differences between arms are noise. Latency is measured on a laptop CPU. The index covers the portal from January 2019, so older alerts are absent, and legacy PDF months enter only through helpers that are not yet a complete pipeline. Regional-language templates await review by a native speaker and are not shown.

\subsection{Threats to validity}
Thresholds were tuned on the development seed only, and the evaluation seed was generated once, but both sets come from the same generator, so they share its blind spots. The evaluation seed was also run twice: three code defects found in the first run were fixed before the second (Section~\ref{sec:runs}). The fixes are general, yet the reported run is no longer a held-out test, and its scores with the oracle user are an optimistic estimate. Collision and sibling traps are built from real batch keys, yet their frequency in the test set is far higher than on a person's shelf. At realistic base rates even a small false-alarm rate can produce more false alarms than true ones, so the positive predictive value of an alarm in use will be lower than the test-set rates suggest.

\subsection{Ethics and safety}
StripCheck gives advice and directs every result to a pharmacist. It never says that a medicine is safe or genuine, never tells anyone to stop a medicine and flags only the listed batch, never a brand. Verdict text comes from fixed templates, and the language model cannot write user-facing text. Text read from packs and alerts enters prompts only as data, the model may choose only among allowed actions, and its endpoint must be on the local machine, which limits what injected text could do. Photos, checks and alert data stay on the user's machine; no personal data is collected, and phone access requires a pairing token. CDSCO's website policy asks that its content be acknowledged, so the alert data is kept locally and cited on every alarm, and this report publishes only derived statistics. StripCheck is a student project and not a CDSCO service, and the interface says so. The code was written with AI coding assistants under the team's direction, and every module was reviewed and tested by the team.
