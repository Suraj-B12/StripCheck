\subsection{Collision and sibling traps}
In the collision scenario the pack carries a listed batch number on a different product. Exact search returns the entry, grading marks the product as a mismatch and rejects the candidate, and the verdict is \NLISTED{} in five steps. A lookup script raises an alarm here. In the sibling scenario every field of the pack agrees with a listed entry, so grading accepts it, but the batch came from OCR. The gate asks the person to type the doubtful characters; the person types \texttt{LM2408R}, the agent rejects the listed key, searches again and returns \NLISTED.

\subsection{The verifier as critic}
The verifier is independent of the drafting code: it re-checks the draft against the evidence in the stored state. Table~\ref{tab:rules} lists its rules. To show the gate at work we passed it a \FLAGGED{} draft for the clean scenario whose batch came from OCR alone. It returned \CANTV{} with the violations \emph{R2: corroborated, confirmed batch evidence is required} and \emph{R8: every used field needs grounded provenance}. On any violation the verifier replaces the draft with the \CANTV{} template and stores the rule identifiers, so an unsupported alarm cannot reach the person.

\subsection{Feedback loop and memory}
When a person corrects a character on a photographed pack, the server stores the pair (read character, printed character) in a confusion table, once per answer. On the next check the prior reorders the variant candidates by the channel score of Section~\ref{sec:impl} and orders the characters the confirmation asks about, and the trace says so (Table~\ref{tab:concepts}, memory row). The question itself adds, from a template: ``Earlier checks on this computer confirmed that the photo reader read B as 8 once. Please still check the printed character yourself.'' The prior never skips the question, because two batches of one product from one maker can differ by exactly the character in doubt. The cabinet is the second memory: after each sync the supervisor runs every saved pack through the same investigator without questions and creates a notification when one now matches a listed entry, or when its printed expiry month is less than 30 days away.
